원칙 1
LLM은 이미지를 직접 보지 않음
비전 모델(MediaPipe/OpenCV)이 feature를 수치로 추출하고, PC2 LLM은 JSON만 수신. 이미지 비용/프라이버시 이슈 해결.
원칙 2
조건부 LLM 호출
TriggerEngine.should_call_llm()이 mode + event 기준으로 판단. 현재 활성 경로는 exercise+session_completed이다.
원칙 3
Fallback 항상 보장
PC2 연결 실패, 타임아웃 발생 시 _mock_response()가 자동 대체. 어떤 상황에서도 결과 카드가 반환됨.
원칙 4
Exercise 중심 SessionMode
현재 활성 모드는 exercise이며, 나머지 분기는 예약 상태다. Vision Pipeline과 프롬프트, 응답 형식은 exercise 기준으로 운영된다.
원칙 5
실시간 피드백 분리
운동 중 카운트/자세 오류는 WebSocket으로 즉시 브로드캐스트. LLM 호출과 별도 경로로 지연 없는 UX 제공.
원칙 6
인메모리 상태 관리
MemoryStore가 세션/feature/result를 메모리에서 관리. Baseline DB(PostgreSQL)는 영속성이 필요한 평소 상태만 저장.
